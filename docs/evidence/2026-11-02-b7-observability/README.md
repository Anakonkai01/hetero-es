# B7 service metrics, readiness and safe JSON request logs

Baseline ea365bfe. Source hashes, tracked patch and new source files identify this implementation. Cloud services use
prometheus-client0.26.0 with one registry per application. Every role exposes health, DB/storage readiness and HTTP
counter/histogram observations by registered route pattern. Unknown methods are OTHER; unmatched routes are _unmatched.
Only scheduler registers business gauges. Scraping reads the DB through a checked dedicated owning PostgreSQL session,
serialized with dispatch. Standby/lost leadership suppresses business values. Graceful shutdown retains that session
until concurrent metrics reads finish. GPU MiB is converted to bytes; absent/invalid/nonfinite/huge values are omitted.
Run/error gauges describe retained snapshots, recovery bytes describe DB-tracked objects, not total bucket inventory.
No object-store listing takes place during a scrape. The design document defines all names, labels, units and limits.

Request JSON has exactly nine safe fields. IDs are generated by the server. Credentials in query/header/body/path and
unexpected exception messages are absent from log/body/metrics; a real loopback Uvicorn fixture also checks stderr.
The middleware consumes unexpected endpoint errors before Uvicorn can print a second credential-bearing traceback.
Split/cloud startup requires Prometheus; the optional-free local desktop all/SQLite/local-auth profile keeps only its
legacy service_up metric. Original test assertions remain intact apart from additions to this new B7 test module.

Final full actual-MinIO-enabled SQLite641 / PostgreSQL669 pass, zero skips. Two known warnings: Starlette's httpx
transition and the intentionally weak RSA test. PostgreSQL target counts and cleanup are in its final receipt/audit.
The initial full suites before the real-transport test passed640/668. Focused final mutation control17 passes on actual
PG; all31 syntactically valid mutants are killed. Initial26/27 is retained: the HTTP counter mutant survived because
the test checked series existence without checking their values. The strengthened test requires1 per completed request
and2 after a repeat. Added storage reservation/quota/filter mutations also fail independently. No equivalence is used.

The graceful-session red log reproduces the actual read/close race. The earlier graceful-metrics red log is only a stale
resource rejection after the old development container disappeared; it is not code-failure evidence. Fresh PG/MinIO
records/loopback port ownership were checked before reuse. Unrepresentable-values red records huge telemetry and run
counter failures. Early focused PG also exposed a minimal SQLite dispatch fixture without operation_lock; the controller
now caches the real Store operation lock with a fallback for that compatible fixture.

The first check-all was interrupted by the owner's pause. Its web-live failure has no usable diagnostic and its later
checks did not complete; it is rejected as whole-suite evidence. The fresh resumed check-all passes every24 steps,
including all browser/Electron contracts,3324 runtime passes/1045 intentional CUDA-hidden skips and626 backend passes
(the15 real-MinIO cases require the explicit MinIO matrix environment). Original/intermediate logs remain separate.

## What this does NOT show

These are isolated CPU/database/storage/HTTP and fixture browser/Electron checks. They do not establish live GPU
telemetry, deployed Prometheus/Grafana/Loki, a real Keycloak realm, GPU/Windows acceptance, installed private desktop
Python dependencies or completion of MiniCloud. B8-B10 and all C remain. The live lab and revoked public device are
untouched. New owned development PG/MinIO resources are preserved for the next milestones. Old private resource records
are retained locally but were not reused. No credentials, signed capabilities, private SQL/dumps or PG client binaries
are archived; changed diagnostic logs have original/redacted hashes. Full A->B->C completion is not claimed.
